# NovaFin: simulated fintech demo

NovaFin is a full-stack demo of a fintech app. It includes a multi-currency wallet, currency exchange, US stock paper trading, QR payments, bank account management, notifications and analytics.

> **Everything is DEMO / SIMULATED.** Balances, exchange rates, stock prices, transfers, bank accounts and QR payments are fictional. No real money moves. Prices are not live market quotes, and NovaFin does not connect to any financial institution.

```
.
├── shared/     @novafin/shared: domain types, seed datasets, decimal-safe engine (used by both apps)
├── backend/    Express + TypeScript REST API (in-memory demo sessions, simulated market)
├── frontend/   Next.js App Router + React + Tailwind + shadcn/ui + Recharts UI (localStorage demo mode)
└── package.json  npm workspaces + root scripts
```

## 1. Requirements

- **Node.js 20.9 or later.** It was developed and tested on Node 22.
- npm 10 or later (bundled with Node).

## 2. Install

```bash
npm install
```

This installs all three workspaces. No API keys, paid services or external accounts are needed.

Optional environment files:

```bash
cp backend/.env.example backend/.env          # PORT, CORS_ORIGIN, MARKET_TICK_MS, SESSION_TTL_MINUTES
cp frontend/.env.example frontend/.env.local  # NEXT_PUBLIC_API_URL (default http://localhost:4000/api)
```

## 3. Run

| Command | What it does |
|---|---|
| `npm run dev` | Runs the API (http://localhost:4000) and the web app (http://localhost:3000) together, with hot reload |
| `npm run build` | Typechecks and bundles the backend, then builds the Next.js app for production |
| `npm start` | Runs both production builds together (run `npm run build` first) |
| `npm test` | Runs all unit and API tests (shared, backend, frontend) |
| `npm run typecheck` | Runs strict TypeScript checks for every workspace |

Open **http://localhost:3000**.

The web app works on its own: if the API is not running, every page still works in localStorage demo mode. **Settings → Backend API** shows whether the API is reachable.

## 4. Demo account

There is no sign-up and there are no passwords. On first visit, NovaFin seeds a demo account in your browser and shows a welcome screen explaining the simulated environment. Click **Enter demo** to continue.

| | |
|---|---|
| User | Alex Morgan, wallet `NVF-4821-7730` |
| Available USD cash | **$25,000.00** |
| Invested stock value | **$8,500.00** at seed prices (AAPL, MSFT, NVDA, VOO, JPM, KO) |
| Other currencies | INR, EUR and GBP balances from past exchanges |
| Bank accounts | 3 fictional accounts: 2 US, 1 India; one awaits verification |
| History | 70+ transactions, 17 notifications, 16 watchlist symbols, 6 saved recipients |

The seed history is generated by replaying a scripted set of operations through the same engine the UI uses. Every balance, holding, order and fee in the history is therefore internally consistent. The size of the opening deposit is chosen so the account ends at exactly $25,000. In the transactions list, historical seed entries are labelled *"historical demo"*. Entries you create are labelled *"Created by you"*.

Net worth = all cash (non-USD converted at demo rates) + market value of holdings. Money that has been invested is no longer counted as cash, so nothing is counted twice.

For the API, `POST /api/auth/demo-login` creates a fresh seeded session and returns a bearer token.

## 5. Reset demo data

- In the UI: **Settings → Reset demo data**, or the avatar menu → **Reset demo data**. This clears every `novafin_*` localStorage key and restores the original seed.
- Through the API: `POST /api/demo/reset` (requires a session).

## 6. How the simulated market works

- `shared/src/market/stocks.seed.ts` holds a typed dataset of **151 US-listed stocks and ETFs**. Each entry has a symbol, name, sector, exchange, price, previous close, change, open, high, low, volume, market cap, description, 90-day price and volume history, and a timestamp. Prices and moves vary from symbol to symbol.
- `shared/src/market/engine.ts` (`tickMarket`) advances prices every 5–10 seconds (7 s by default; configurable in Settings):
  - A market-wide factor is combined with each stock's own noise, scaled to that stock's volatility, so some stocks rise while others fall.
  - Each tick moves at most ±1.2%. The total daily move is capped at ±18%, and prices drift back toward the previous close as they approach the cap.
  - Price, absolute change and % change are always updated together.
  - The random generator is deterministic and its state is persisted (`novafin_market_state`), so state is not re-randomised on React renders and the latest prices survive a refresh.
- Updates **pause while the browser tab is hidden** and resume when it becomes visible again.
- Chart history for 1D, 1W, 1M, 3M, 1Y and 5Y is **synthetic**. It comes from a seeded random walk per symbol and is cached, so a chart looks the same on every render. The last point always equals the current simulated price. These are not real historical market records.
- The **US market open/closed** badge uses real New York trading hours (Mon–Fri 09:30–16:00 ET, holidays ignored). It is for display only. The simulator runs whether or not the real market is open.
- Every market view shows a **SIMULATED MARKET DATA** badge.

Paper trading uses the demo USD wallet:
- Market orders fill at the current simulated price.
- Fractional shares are supported (up to 6 decimals).
- Commission is 0.1% of order value, with a minimum of $0.01 and a maximum of $9.99.
- After a buy, the average price and cost basis are recalculated.
- Sells use proportional cost basis to compute realized P/L.
- Rejected orders (for example insufficient cash or insufficient shares) are recorded in order history.

## 7. QR payments

The payload format is specific to NovaFin. It is a JSON object of type `novafin.payment-request` with:
- version
- request id
- payee wallet id
- name
- amount
- currency
- optional note
- expiry
- `demo: true`
- a checksum

The payload is **not** a UPI, EMVCo, ACH or wire instruction.

- **Generate.** Enter an amount, currency, note and expiry. You get a QR preview (`qrcode.react`), plus options to **download a PNG**, **copy the details** or **share** them (Web Share API, or the clipboard as a fallback). **Simulate payer** lets another demo user pay your request, so you can test without a second device.
- **Scan.** Scanning uses `html5-qrcode`. The camera is requested **only after you click "Start camera"**. Permission, missing-camera and non-HTTPS errors each get a clear message. You can also **upload an image** or paste a payload instead.
- **Validation.** Before anything is paid, the payload is validated against:
  - a strict zod schema that rejects unknown fields
  - the checksum, which catches tampering
  - the expiry time
  - a rule that you cannot pay your own request
  - **replay protection**: each request id can only be paid once
  - your balance

  Scanning never moves money. You always get a confirmation screen, and funds are deducted only after you click **Confirm & pay**.
- **Test codes tab.** Four fictional merchant QR codes you can download, upload or pay to try the full flow.

Camera access requires `localhost` or HTTPS.

## 9. Architecture notes

- **Business logic lives in one place.** Every financial calculation is in `@novafin/shared`:
  - fees
  - FX quotes
  - trade quotes
  - average price and P/L
  - balance history

  Each operation is a pure function `(state, input) => { state, result }` that throws a typed `DemoError`. Both the Express API and the browser call the same functions. The UI does not repeat the arithmetic. Money math uses `decimal.js` and is rounded to each currency's minor units.
- **Browser persistence.** `frontend/lib/storage/storage.ts` stores each slice under its own key (`novafin_demo_user`, `novafin_wallet`, `novafin_bank_accounts`, `novafin_transactions`, `novafin_portfolio`, `novafin_orders`, `novafin_watchlist`, `novafin_notifications`, `novafin_market_state`, `novafin_exchange_history`, `novafin_settings`, plus `novafin_recipients`, `novafin_qr`, `novafin_meta`). The storage layer provides:
  - a schema version and a migration table
  - JSON parse recovery: non-critical slices fall back to seed data, while corruption in a ledger slice triggers a full reseed so balances can never become inconsistent
  - writes only for slices that changed
  - sync between browser tabs via the `storage` event
- **State store.** `frontend/lib/store/demo-store.ts` is a small `useSyncExternalStore` store. It never touches localStorage during server rendering, and app pages render after the client store has loaded, so there are no hydration mismatches.
- **API adapter.** `frontend/lib/api/demo-api.ts` is what the UI calls. It adds simulated latency, blocks double submission while an operation is in flight, and records rejected orders. `frontend/lib/api/backend.ts` is a typed client for the Express API.
- **localStorage is browser-local.** The backend does not and cannot read it. The backend keeps its own **in-memory** demo sessions (`backend/src/services/session.service.ts`), which are lost when the server restarts. Neither store is a secure production ledger.

## 10. REST API

Base URL: `http://localhost:4000/api`.

Every response has the shape `{ success: true, data, meta? }` or `{ success: false, error: { code, message, details? } }` and carries an `X-NovaFin-Demo: simulated` header.

Endpoints marked 🔒 need `Authorization: Bearer <token>` from `demo-login`.

| Method & path | Description |
|---|---|
| `GET /health` | Health check |
| `POST /auth/demo-login` | Create a seeded demo session → `{ token, user }` |
| `POST /auth/logout` 🔒 · `GET /auth/me` 🔒 | End the session / get the current user |
| `GET /wallet` 🔒 | Balances, net worth, totals |
| `POST /wallet/deposit` 🔒 | `{ amount, method, currency? }` |
| `POST /wallet/withdraw` 🔒 | `{ amount, bankAccountId, speed }` |
| `GET /bank-accounts` 🔒 · `POST /bank-accounts` 🔒 | List / add an account (only the last 4 digits are kept) |
| `PATCH /bank-accounts/:id` 🔒 · `DELETE /bank-accounts/:id` 🔒 | Rename, set default, verify / remove |
| `POST /transfers` 🔒 · `GET /transfers` 🔒 · `GET /transfers/recipients` 🔒 | Send money / list transfers / list recipients |
| `GET /exchange/rates` · `GET /exchange/quote?from&to&amount` · `GET /exchange/rates/history` | Simulated rates and quotes |
| `POST /exchange` 🔒 · `GET /exchange/history` 🔒 | Convert currency / conversion history |
| `GET /stocks?search&sector&type&sort&order&page&pageSize&minChange&maxChange` | Paginated stock list |
| `GET /stocks/:symbol` · `GET /stocks/:symbol/history?range=1D\|1W\|1M\|3M\|1Y\|5Y` | Stock detail and synthetic history |
| `GET /market/summary` | Indices, gainers, losers, most active, sectors, market status |
| `GET /portfolio` 🔒 | Positions with live valuation and P/L |
| `POST /orders/buy` 🔒 · `POST /orders/sell` 🔒 | `{ symbol, quantity }`; the server sets the price, and a client-supplied price is rejected |
| `GET /orders` 🔒 | Order history (`?status&side`) |
| `GET /watchlist` 🔒 · `POST /watchlist` 🔒 · `PATCH /watchlist/:symbol` 🔒 · `DELETE /watchlist/:symbol` 🔒 | Watchlist and price alerts |
| `GET /transactions` 🔒 · `GET /transactions/:id` 🔒 · `POST /transactions/:id/cancel` 🔒 | Ledger (search, category, status, from, to, sort, page) / detail / cancel a pending transaction |
| `GET /notifications` 🔒 · `PATCH /notifications/:id/read` 🔒 · `POST /notifications/read-all` 🔒 · `DELETE /notifications/:id` 🔒 | Notification center |
| `POST /qr/payment-request` 🔒 · `GET /qr/requests` 🔒 · `POST /qr/requests/:id/cancel` 🔒 | Create, list and cancel payment requests |
| `POST /qr/validate` 🔒 | Validate a payload only; never moves money |
| `POST /qr/pay` 🔒 | `{ payload, confirm: true }`; a replayed request returns 409 |
| `GET /settings` 🔒 · `PATCH /settings` 🔒 | Demo preferences |
| `POST /demo/reset` 🔒 | Restore the seed state for this session |

Status codes: 200, 201, 400 (validation / bad JSON), 401, 404, 409 (duplicate / invalid state), 410 (expired QR), 413, 422 (insufficient funds / shares, limits), 500.

## 11. Simulated here vs. needed in production

| Feature | In this demo | Needed in production |
|---|---|---|
| Deposits & withdrawals | Ledger entries; settlement is a timer | Licensed payment processor or banking partner (ACH / RTP / IMPS / SEPA), KYC/AML |
| Bank accounts | Fictional banks; numbers stored masked in the browser | Open-banking aggregator or micro-deposit verification, encrypted server-side vault |
| Currency exchange | Static illustrative rates, 1% fee | Licensed FX provider with live quotes and rate locking |
| Stock market & trading | Seeded dataset, random-walk simulator, instant fills | Market data licence and a broker-dealer / execution API, order routing, settlement |
| QR payments | App-specific JSON with a non-cryptographic checksum | Server-signed payloads or a scheme like UPI/EMVCo through a PSP |
| Auth & storage | No passwords; localStorage and in-memory sessions | Real authentication, MFA, a durable audited double-entry ledger database |
| Notifications | In-app list and toasts | Push, email and SMS providers |

Never enter real credentials, card numbers, PINs or OTPs into this demo.

## Troubleshooting

- **The backend build cannot resolve `@novafin/shared`.** This happens when a stray Yarn Plug'n'Play file (`.pnp.cjs`) exists in a parent folder such as your home directory. `backend/tsup.config.ts` already works around it by resolving the shared package by path.
- **Windows `EBUSY` during `next build`.** Antivirus or the search indexer sometimes locks `.next`. Delete `frontend/.next` and build again.
- **The camera does not start.** Open the app on `http://localhost:3000` (or over HTTPS), allow camera access, or use **Upload image** instead.
